## 목적과 경계

이 정책은 제품 밖에서 준비한 정규화 문서를 `source_document`로 저장하기 전에 기존 원문 계보와 같은 자료인지 새로운 독립 자료인지 판정하는 규칙을 정한다. Evidence Group은 같은 원문에서 복제·재게시·전재·번역된 문서를 독립 근거 하나로 세기 위한 단위이며, 같은 사건을 다룬 기사 묶음이나 출처 신뢰도 등급이 아니다. 데모의 사용자 파일 업로드는 외부 URL이 없을 수 있는 신규 입력으로 별도 자동 저장 경계를 사용하며, 이 정책의 외부 계보 판정을 완료했다는 뜻이 아니다.

판정 입력은 계약에 맞는 정규화 본문과 SHA-256 `body_hash`, 자료 준비 레이어가 부여한 `source_key`, 원천의 안정된 문서 식별자, canonical URL, 확인된 원문 링크와 제목·작성자·발행처·언어·게시 시점이다. PostgreSQL FTS는 기존 후보를 찾는 데만 쓴다. #110의 출처 허용과 적재 정책은 이 판정 앞에서 입력 자격을 정한다.

자동 판정에 쓰는 원천 식별자는 반드시 `원천 namespace + 원천 문서 ID` 쌍이어야 하며 발행처마다 겹칠 수 있는 로컬 ID만 사용하지 않는다. namespace는 식별자를 발급한 DNS host 또는 승인된 원천 코드의 소문자 ASCII 값이고, 문서 ID는 앞뒤 공백을 제거하되 원천이 보장한 대소문자를 유지하는 불투명 값이다. 확인된 원문 링크는 문서가 밝힌 전재 관계나 사람의 원문 대조로 확정된 링크를 뜻하며 URL 문자열의 유사성을 뜻하지 않는다. 이 식별자와 확인 근거는 해당 `source_key`와 함께 승인된 준비 기록에 남겨 동일 입력을 다시 처리할 때 조회할 수 있어야 한다. 판정할 때는 기존 `source_document.source_key`에 연결된 준비 기록에서 같은 식별자·원문 링크를 찾고 현재 `evidence_group_id`를 읽는다. 전달 형식은 후속 입력 경계에서 정하고 제품 DB 필드나 판정 이력 테이블로 만들지 않는다. 준비 기록을 재조회할 수 없으면 결정적 신호로 사용하지 않고 검토 후보로 낮춘다.

제품 DB에 전달하는 결과는 기존 또는 새 `evidence_group_id`를 가진 `source_document`뿐이다. 후보 목록, 점수, 판정 이유, 검토자와 배정 이력은 제품 DB에 저장하지 않으며 `evidence_group_assignment`나 준비용 embedding을 추가하지 않는다.

## 판정 결과

자료 준비 레이어는 다음 셋 중 하나로 처리한다. 결과 이름은 준비 과정의 설명이며 새 DB enum이나 상태 컬럼이 아니다.

- 기존 묶음 선택: 결정적 신호가 가리키는 Evidence Group 하나를 사용한다.
- 새 묶음 생성: 기존 계보 후보가 없거나 검토로 독립 자료임을 확인한 뒤 새 Evidence Group을 만들고 사용한다.
- 검토 보류: 신호가 서로 충돌하거나 후보만으로 계보를 확정할 수 없으면 `source_document`를 저장하지 않는다.

## 결정적 처리 순서

한 준비 배치의 후보와 기존 문서를 먼저 하나의 집합으로 보고, 아래 1~3단계의 결정적 신호가 연결하는 문서의 전이적 묶음을 입력 순서와 무관하게 계산한다. 원문보다 재게시·번역 문서가 먼저 나타나도 확인된 원천 식별자나 원문 링크가 같으면 같은 묶음에 들어간다. 4단계 신호는 후보를 찾을 뿐 이 묶음의 연결선이 아니다.

1. `body_hash`가 정확히 같은 문서를 연결한다.
2. `source_key`가 같은 기존 버전과 배치 후보를 연결한다.
3. 정규화한 `원천 namespace + 원천 문서 ID` 또는 재조회 가능한 확인된 원문 링크가 같은 문서를 연결한다. 명시적으로 확인된 재게시·전재·번역은 본문 해시가 달라도 원문과 연결한다.
4. canonical URL, 제목·작성자·발행처·언어·게시 시점과 PostgreSQL FTS로 검토 후보를 찾는다. 이 신호들은 비슷한 문서를 찾을 뿐 같은 계보를 자동 확정하지 않는다.

각 전이적 묶음이 가리키는 기존 Evidence Group을 모아 다음처럼 결정한다.

- 기존 Evidence Group이 하나면 배치 후보 전체에 그 묶음을 사용한다.
- 기존 Evidence Group이 없고 4단계 후보도 없으면 배치 후보 전체에 새 묶음 하나를 만든다.
- 기존 Evidence Group이 없지만 4단계 후보가 있으면 독립 자료인지 검토한다. 독립임을 확인하면 서로 다른 전이적 묶음마다 새 묶음을 만들고, 같은 계보임을 확인하면 연결을 추가해 다시 계산한다.
- 기존 Evidence Group이 둘 이상이면 기존 분류나 입력 신호가 충돌한 상태이므로 전이적 묶음 전체를 저장하지 않는다.
- 원문 계보를 확인하지 못한 4단계 후보가 남으면 해당 후보의 저장을 보류한다.

canonical URL이 같거나 비슷하다는 사실만으로 자동 병합하지 않는다. 이미 승인된 안정된 canonical URL이 `source_key`의 근거라면 2단계의 기존 `source_key` 규칙을 적용하고, 새 입력의 URL 문자열만 일치하면 4단계의 검토 후보로만 취급한다.

## 문서 버전과의 관계

Evidence Group 판정과 문서 버전 판정은 구분한다.

- 같은 `source_key`와 같은 불변 문서 내용이면 새 행을 만들지 않고 `last_checked_at`, `last_check_status`만 갱신한다.
- 같은 `source_key`에서 본문이나 불변 버전 메타데이터가 바뀌면 다음 `version_no`의 새 `source_document`를 만들되 기존 버전과 같은 Evidence Group을 사용한다.
- 다른 `source_key`의 문서가 같은 `body_hash`를 가지거나 확인된 재게시·전재·번역이면 문서 행은 서로 달라도 Evidence Group은 하나다.
- 같은 사건을 서로 독립적으로 취재·작성한 문서는 주제·사실·게시 시점이 비슷해도 서로 다른 Evidence Group이다.

묶음 선택과 `source_document` 저장은 한 트랜잭션 경계에서 처리한다. 배치 안에서는 결정적 연결을 모두 만든 뒤 묶음을 확정하고, 각 전이적 묶음에서 `(source_key, body_hash, canonical_url)`을 사전순으로 비교한 최솟값을 기준으로 묶음 사이 처리 순서를 고정한다. 같은 결정적 식별자를 동시에 처리하는 준비 경로는 배정 확정을 직렬화하고 저장 직전에 기존 묶음을 다시 확인해야 한다. 구체적인 worker와 잠금 방식은 이 정책을 소비하는 적재 경로의 별도 승인 범위이며 이번 문서에 포함하지 않는다.

## 모호성과 정정

다음 경우에는 새 묶음을 임의로 만들거나 가장 작은 ID·가장 이른 게시일·가장 높은 FTS 순위를 택하지 않는다.

- 같은 `body_hash`, `source_key` 또는 확인된 원문 식별자가 서로 다른 Evidence Group을 가리킨다.
- 비슷한 제목·본문 일부·게시 시점만 있고 재게시인지 독립 기사인지 확인할 수 없다.
- 원문 링크가 순환하거나 서로 다른 원문을 가리킨다.
- 추출 오류 때문에 본문이 실제 문서가 아니라 공통 머리글·푸터로 보인다.

검토자는 원천의 안정된 식별자, 문서가 밝힌 원문·전재 관계와 실제 본문을 확인해 기존 묶음 선택 또는 새 묶음 생성을 확정한다. 검토 기록이 필요하면 제품 DB 밖의 승인된 준비 기록에 두며, 현재 schema에 판정 이력이나 actor를 추가하지 않는다.

기존 판정 오류는 [논리 스키마](logical-schema.md#52-source_document)의 승인된 정정 경로로 `source_document.evidence_group_id`를 직접 수정한다. 같은 계보 판정의 영향을 받는 문서를 함께 정정하고, 독립 근거 수와 해당 근거를 사용하는 공개 결과를 다시 검증·준비해야 한다. 과거 배정 이력은 보존하지 않는다.

## 대표 검증 사례

다음 표는 같은 입력을 반복해도 같은 계보 판단이 나오는지, 독립 근거를 잘못 합치거나 같은 계보를 중복 생성하지 않는지 확인하는 최소 사례다. [#131 GDELT 시연 corpus 결과](../../review/131-gdelt-collection/README.md)의 공개 manifest는 URL·본문 해시·발행처·제목 사례만 제공한다. `source_key` 일치와 독립 취재·전재 관계는 manifest가 증명하지 않으므로 각 행에 명시한 합성 전제이며, 수집기의 중복 제거 상태를 제품 저장 결과나 추출 품질 증거로 간주하지 않는다.

| 사례 | 입력과 신호 | 기대 결과 | 막아야 할 오류 |
| --- | --- | --- | --- |
| 같은 URL 재발견 | #131의 `DUPLICATE_URL`은 같은 canonical URL의 반복을 제공한다. fixture는 기존 `source_key`와 불변 내용도 같다고 전제한다. | 새 문서나 묶음을 만들지 않고 마지막 확인 정보만 갱신한다. | 같은 문서와 묶음의 중복 생성 |
| URL 변형의 같은 본문 | #131의 `DUPLICATE_BODY`처럼 `www`·모바일 주소가 다르지만 전체 `body_hash`가 같다. | 서로 다른 문서로 보존할 필요가 있더라도 Evidence Group은 하나다. | URL 차이로 인한 duplicate group |
| 같은 문서의 수정 버전 | 기존 `source_key`는 같고 본문 또는 불변 메타데이터가 바뀌었다. | 다음 문서 버전을 만들고 기존 Evidence Group을 유지한다. | 수정본을 독립 근거로 중복 계산 |
| 확인된 재게시·번역 | 본문 해시는 다르지만 원천 식별자나 확인된 원문 링크가 한 원문을 가리킨다. | 원문과 같은 Evidence Group을 사용한다. | 편집·번역본의 duplicate group |
| 같은 사건의 독립 기사 | #131의 SK하이닉스 나스닥 관련 선택 행은 여러 발행처와 서로 다른 본문 해시를 제공한다. fixture는 각 `source_key`가 다르고 원문 대조에서 전재 관계가 없다고 확인됐다고 전제한다. | 결정적 연결이 없는 독립 계보마다 새 Evidence Group을 만든다. | metadata·FTS 유사도로 인한 false merge |
| 결정적 신호 충돌 | `body_hash`는 묶음 A, 기존 `source_key`는 묶음 B를 가리킨다. | 문서를 저장하지 않고 기존 분류 또는 입력 오류를 검토한다. | 임의 우선순위로 잘못된 묶음 선택 |
| 유사 후보만 존재 | 제목·날짜·FTS 결과는 비슷하지만 원문 관계를 확인할 수 없다. | 검토가 끝날 때까지 저장하지 않는다. | 불확실한 자동 병합 또는 자동 분리 |

동일 사례를 입력 순서만 바꿔 반복하고, 기존 묶음이 있는 재처리와 빈 DB에서 한 배치를 처리하는 경우를 각각 확인한다. 확인된 원문보다 재게시·번역 자료가 먼저 오는 순서도 포함한다. 결과 ID의 숫자 자체가 아니라 같은 계보끼리 같은 ID를 공유하고 독립 계보끼리 다른 ID를 갖는지가 기준이다.
